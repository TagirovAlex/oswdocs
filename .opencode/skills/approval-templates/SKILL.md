# Шаблоны маршрутов

Таблицы маршрута: `ad_services, approval_stages, stage_assignees, route_profiles, route_profile_steps`
(миграция 0008). Старые `templates*` пустые и в подборе не участвуют. Все правит только
разрешённая группа AD (`SED_ADMINS`); в заявку пишется снимок подбора — правка справочников
не меняет выданный маршрут.

## Железные правила

- Подбор маршрута — по службе сотрудника из AD (`route_mode=auto`): профиль → его шаги → снятые
  (`dismissed_stages`) и добавленные (`added_stages`) этапы. Службы — справочник `ad_services`
  (наполняется синком подразделений AD, там же `blank_kind` офис/линейный). Нет профиля или
  нет карточки AD/связи → понятная ошибка (см. `link_state`) или штатный ручной конструктор от ОК.
- Виды этапов: `ad_group` (группа AD), `stage_roster` (состав в `stage_assignees`; пустой реестр →
  этап заблокирован), `manager_ad` (руководитель сотрудника из AD).
- Категория не выводится автоматически: подсказки из AD/флага МОЛ — только подсветка, решает ОК.
- Ручной конструктор и правка выданного маршрута — только разрешенная группа; любое изменение по ходу — в `audit_log`.
- Резолверы шагов: `owner_kind` в справочнике этапа (`ad_group`/`stage_roster`/`manager_ad`),
  для ручного режима — конструктор с группами/сотрудниками. Владелец шага — группа AD, отметку
  ставит любой её член; бланк печатает ФИО персональных исполнителей (групповые — дописывают от руки).
- `require_paper_signature` — флаг на шаг, включается без кода. `require_comment` — флаг на шаг (по умолчанию false): при согласовании комментарий опционален, при отказе/возврате на доработку — обязателен всегда. `position_escalation` (должность→часы, пусто=выкл), `approval_ttl_days` — из настроек.

## Приемка правки

Шаблон фильтруется корректно, ручной маршрут валидируется (все исполнители найдены в AD/группах), правки логируются.
