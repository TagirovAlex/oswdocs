# Маршруты: бланки, этапы, конструктор

Таблицы маршрута: `ad_services, approval_stages, stage_assignees, route_profiles, route_profile_steps`
(миграция 0008) и `blanks, blank_steps` (миграции 0012/0013/0014). Шаг бланка САМОСТОЯТЕЛЬНЫЙ: этап
справочника ему не нужен (миграция 0014), справочник этапов остался запасным путём подбора по службе.
Старые `templates*` пустые и в подборе не участвуют; ключи `templates`/`position_to_category` (0014)
и мёртвые `doc_templates`/`position_sets` (0016) удалены. Все правит только разрешённая группа AD
(`SED_ADMINS`); в заявку пишется снимок подбора/бланка — правка справочников не меняет выданный
маршрут.

## Железные правила

- Основной путь — бланк выбирает сотрудник ОК (`POST /requests` с `blank_id`, список для селекта
  `GET /requests/route/blanks`). Шаг бланка задаётся сам: `title`/`stage_lines` (текст),
  `executor_kind` (`people` — `assignees`, `ad_group` — `owner_group`, `manager_ad` — руководитель
  сотрудника в AD), `approval_mode`, `optional`, `require_comment`. Замена состава бланка — одной
  транзакцией, `version` растёт, дубль порядка и несогласованный исполнитель — 422 на границе.
- **Снятие шага бланка — по номеру** (`dismissed_step_orders: list[int]`, `_dismiss_blank_steps`):
  кода этапа у шага нет. Отказ 422: номер вне состава (с перечнем), номер у обязательного шага
  (`optional=false` — с номером и названием), сняты все шаги. Этапы профиля службы и ручного
  маршрута снимаются/добавляются по кодам (`dismissed_stages`/`added_stages`) — это другой список.
  `optional` шага едет в снимок заявки (`request_steps.optional`, миграция 0015).
- Подбор маршрута по службе сотрудника из AD (`route_mode=auto`, профиль → его шаги) — запасной
  путь за настройкой `blank_autopick` (только значение `on` включает; по умолчанию `off`).
  Нет профиля или нет карточки AD/связи → понятная ошибка (см. `link_state`) или штатный ручной
  конструктор от ОК. Бланк не выбран при `blank_autopick=off` — ОДИНАКОВЫЙ 422 в предпросмотре и
  создании с перечнем вариантов (выбрать бланк либо задать маршрут вручную); бланк без шагов
  выбрать нельзя.
- Виды исполнителя у ЭТАПА справочника: `ad_group` (группа AD), `stage_roster` (состав в
  `stage_assignees`; пустой реестр → этап заблокирован), `manager_ad` (руководитель сотрудника
  из AD). У шага бланка вместо этого свой `executor_kind`.
- Режим шага (`blank_steps.approval_mode`) выбирает сотрудник ОК: `parallel` — закрывает любой из
  ответственных, `sequential` (по умолчанию) — все. В заявке снимок: `assignees` (логины),
  `approval_mode`, `approvals` ({sam, at, decision, comment}); `assignee` — первый из списка.
  Повторная отметка — 409, отказ/возврат действует сразу от любого ответственного.
- Категория не выводится автоматически: подсказки из AD/флага МОЛ — только подсветка, решает ОК.
- Ручной конструктор и правка выданного маршрута — только разрешенная группа; любое изменение по ходу — в `audit_log`.
- Резолверы шагов: у шага бланка — `executor_kind` (`by_user`/`by_group`/`ad_direct_manager`),
  у этапа справочника — `owner_kind` (`ad_group`/`stage_roster`/`manager_ad`), для ручного режима —
  конструктор с группами/сотрудниками. Владелец шага — группа AD, отметку ставит любой её член;
  бланк печатает ФИО всех персональных ответственных (групповые — дописывают от руки).
- `require_paper_signature` — флаг на шаг, включается без кода. `require_comment` — флаг на шаг (по умолчанию false): при согласовании комментарий опционален, при отказе/возврате на доработку — обязателен всегда. `position_escalation` (должность→часы, пусто=выкл), `approval_ttl_days` — из настроек.

## Приемка правки

Состав бланка сохраняется (шаг со своим текстом и согласующими), снятие шага бланка по номеру даёт
422 на несогласованный номер/обязательный шаг/снятие всего маршрута, ручной маршрут валидируется
(все исполнители найдены в AD/группах), правки логируются.
