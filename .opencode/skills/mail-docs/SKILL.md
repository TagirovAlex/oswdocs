# Бланки и письма

Печать — по запросу из карточки заявки (`POST /requests/{id}/print`), обычный принтер в ОК.
Файлов-шаблонов `.docx` нет: документ собирается из данных заявки.

## Железные правила

- Бланк = справочник (`blanks`/`blank_steps`, миграции 0012/0013): набор этапов, который выбирает
  сотрудник ОК; в заявку пишется снимок (`blank_id/blank_name/blank_version/blank_layout` плюс
  тексты, ответственные и режим шага). Движок печати: `python-docx` (`docs.build_blank_document`)
  → PDF через LibreOffice headless. QR с `request_id` обязателен.
- Макет печати — два встроенных пресета `office`/`line` (`docs.LAYOUT_PRESETS`), выбирает
  `blank_layout` из снимка; `ad_services.blank_kind` в оформлении не участвует.
- Ключи настроек `doc_templates`/`position_sets` и ручки файлов-бланков удалены — вернуться к
  файловым шаблонам без решения человека нельзя (см. `TEMPLATES.md`).
- Вариант печати 1: PDF отдаётся `pdf_b64` в ответе, версии документов в БД НЕ накапливаются,
  временные файлы (docx/pdf/qr) удаляются. Перепечатка — снова печать текущего состояния.
- Несколько ответственных: в колонке «Ответственный» — все ответственные шага (`assignees`),
  групповой шаг печатается по `owner_group`; письмо «назначена» уходит всем, кто ещё не отметился.
- Где подпись строго требуется — флаг `require_paper_signature` из настроек, включается без кода.
- Письма `mail_templates` (Jinja HTML, корп. вид): «есть документ» + ссылка на заявку. Отправка
  через внутренний Exchange SMTP на `mail` из AD. Очередь `mail_queue` с ретраями, события v1:
  `назначена → напоминание → эскалация → закрыта/возврат`.
- Скан заявления опционален: лимиты `scan_max_mb`, хранение `scan_retention_days` — из настроек.
  ПДн (отпуск и др.) в бланки/письма не включать.

## Приемка правки

DOCX и PDF собираются из данных по снимку бланка, QR сканируется в заявку, письмо уходит с корп. шапкой
(адресаты — ответственные, ещё не отметившиеся), очередь переживает рестарт worker.
