# Бланки и письма

Печать — по запросу из карточки заявки (`POST /requests/{id}/print`), обычный принтер в ОК.
Файлов-шаблонов `.docx` нет: документ собирается из данных заявки.

## Железные правила

- Бланк = справочник (`blanks`/`blank_steps`, миграции 0012/0013/0014) + справочник шагов
  (`step_catalog`, миграция 0018 — переиспользуемые заготовки, в бланк берутся копией «Взять из
  справочника»): набор СВОИХ шагов, который выбирает сотрудник ОК (этап справочника шагу не нужен).
  В заявку пишется снимок
  (`blank_id/blank_name/blank_version/blank_header_html/blank_footer_lines` плюс
  тексты, ответственные, режим и «шаг можно снять» каждого шага). Движок печати: `python-docx`
  (`docs.build_blank_document`) → PDF через LibreOffice headless. QR с `request_id` обязателен.
- Шапка (`blanks.header_html`, редактор TipTap) и подвал (`blanks.footer_lines`) печатаются ПО
  СНИМКУ заявки — правка справочника уже выданные заявки не меняет.
- Плейсхолдеры печати подставляются в шапку, подвал и текст шага: `{fio}`, `{position}`,
  `{department}`, `{tab_num}`, `{enterprise}`, `{blank_name}`, `{subject}`, `{content}`, `{date}`,
  `{dismissal_date}`, `{steps}`, `{manager}` (контракт — решение человека, `docs.blank_placeholders`).
  Значения ЭКРАНИРУЮТСЯ (свободный текст заявки не должен стать разметкой бланка), неизвестный
  плейсхолдер остаётся текстом. `{dismissal_date}` читается по ключу заявки по строке СПЕЦИАЛЬНОГО
  сотрудника (включая уже уволенного), `{manager}` — из зеркала AD `users`.
- Печать — ЕДИНАЯ вёрстка (макета/пресетов нет, поле `blank_layout` снято миграцией 0018): шапка,
  затем каждый шаг отдельным блоком строк («№. Название (последовательно/параллельно)», текст,
  «Ответственный: …», «Отметка/дата: …»), затем подвал; `ad_services.blank_kind` в оформлении не
  участвует.
- Ключи настроек `doc_templates`/`position_sets` (миграция 0016) и ручки файлов-бланков удалены —
  вернуться к файловым шаблонам без решения человека нельзя (см. `TEMPLATES.md`).
- Вариант печати 1: PDF отдаётся `pdf_b64` в ответе, версии документов в БД НЕ накапливаются,
  временные файлы (docx/pdf/qr) удаляются. Перепечатка — снова печать текущего состояния.
- Несколько ответственных: в строке «Ответственный» — все ответственные шага (`assignees`) через
  запятую, групповой шаг печатается по `owner_group`; письмо «назначена» уходит всем, кто ещё не
  отметился.
- Где подпись строго требуется — флаг `require_paper_signature` из настроек, включается без кода.
- Письма `mail_templates` (Jinja HTML, корп. вид): «есть документ» + ссылка на заявку. Отправка
  через внутренний Exchange SMTP на `mail` из AD. Очередь `mail_queue` с ретраями, события v1:
  `назначена → напоминание → эскалация → закрыта/возврат`.
- Скан заявления опционален: лимиты `scan_max_mb`, хранение `scan_retention_days` — из настроек.
  ПДн (отпуск и др.) в бланки/письма не включать.

## Приемка правки

DOCX и PDF собираются из данных по снимку бланка (шапка, подвал и текст шага — с подставленными
плейсхолдерами, значения не разъезжаются в разметку), QR сканируется в заявку, письмо уходит с
корп. шапкой (адресаты — ответственные, ещё не отметившиеся), очередь переживает рестарт worker.
