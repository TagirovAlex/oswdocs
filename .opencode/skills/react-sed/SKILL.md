# React SPA SED

Фронтенд Фазы 5 (README п.6): статика собирается в `frontend/Dockerfile`, отдаётся через `proxy` (отдельного рантайм-сервиса нет).

## Железные правила

- UI — только по матрицам ролей README п.1: ОК — всё + полная карточка, владелец — свои задачи + урезанная карточка (без таб.№/предприятия/ключа сотрудника; ФИО и служба заявки видны всем — решение человека 2026-10-14), админы — всё + настройки, остальные — ничего.
- Логин — через `/auth` (LDAPS bind на стороне API); пароли и токены в localStorage не хранить.
- Создание ОК: предприятие → сотрудник → выбор бланка (`GET /requests/route/blanks`) → маршрут →
  печать; отметки владельца — только свои шаги, у шага видны все ответственные и прогресс отметок.
- Вкладки по ролям (`layout.tsx`, `visibleTabs`): «Заявки» и **«Заместители» — всем
  вошедшим без блоков прав, сразу после «Заявки»** (личный раздел сотрудника, решение
  человека 2026-10-15), «Справочник» — по `employee_directory`, «Сопоставление» — по
  `link_match`, «Настройки» — по `settings_content`/`settings_infra`. Отдельной вкладки
  «Создание» нет: создание открывает кнопка «Создать заявку» (окно `?view=create`).
  Лишних вкладок быть не должно.
- **Личный раздел «Заместители»** (`substitutes.tsx`): список своих записей
  «я → мой заместитель» и форма их правки через
  `GET/POST/PUT/DELETE /api/substitutes/my` (`settings-client.tsx`: `getMySubstitutes`/
  `createMySubstitute`/`updateMySubstitute`/`deleteMySubstitute`, тело `MySubstituteInput`
  без `principal_sam` — сотрудник всегда из сессии). Проверок блоков прав в UI нет:
  сервер и так отдаёт только свои записи. Заместителя выбирают **модалкой подбора**
  `DeputySearchModal` (поиск с debounce 300 мс по `GET /api/substitutes/candidates`
  через `searchSubstituteCandidates`, ответ `{items, total, page, page_size}`) — НЕ
  поиском по AD: `/api/ad/search` закрыт блоком `employee_directory`, и для сотрудника
  вкладка была мертвой. Показ срока и тип `SubstituteCandidate` живут в общем модуле
  `substitutes-shared.ts` (его берёт и админский справочник).
- В админке настроек вкладка «Бланки» (только admin): карточка бланка (шапка `header_html` и подвал
  `footer_lines` с кнопками вставки плейсхолдеров) и собственные шаги бланка — название/текст, вид
  исполнителя (`executor_kind`: список согласующих / группа AD / руководитель), режим
  `parallel`/`sequential`, флаги `optional`/`require_comment`. Этапа справочника у шага бланка нет.
  Вкладка «Шаблоны» удалена (легаси), редактор писем — на вкладке «Письма». Текст шага и шапка
  правятся визуальным редактором (`rich-text.tsx`, TipTap), HTML доходит до печати. UI загрузки
  docx-шаблонов больше нет. Вкладка «Заместители» в настройках — по блоку
  `settings_substitutes`: **управление ВСЕМ справочником** (не только своими записями) —
  «сотрудник → заместитель» (оба выбираются поиском в AD), интервал действия
  датами (`<input type="date">`, пустая конечная — бессрочно), флажок «слать письма
  заместителю», комментарий. Это вторая точка входа в один справочник, а не другой
  справочник. Списки API приходят МАССИВОМ — обёртка `{items: …}`
  для `/settings/substitutes` не применяется.
- Вкладка «Инфра» (`admin-settings.tsx`, блок `settings_infra` — только администратор):
  инфраструктурные настройки, в том числе **«Лимит заместителей на сотрудника
  (`substitute_deputies_limit`)»** — `aria-label="Лимит заместителей"`, `type="number"`,
  значение из `GET /settings`, уходит в `PUT /settings` тем же ключом; ключа в ответе
  нет (старый бэкенд/не засеян) — показывается запасное `SUBSTITUTE_DEPUTIES_LIMIT_FALLBACK
  = 3`, чтобы поле не было пустым. Хардкод значения в UI означал бы, что серверная
  настройка не работает; срок действия записи при этом сервер считает сам («сегодня» по
  часовой зоне системы). Личный раздел «Заместители» (`substitutes.tsx`) этого поля не
  показывает: лимит настраивает администратор, сотрудник только получает 422.
- Карточка заявки: `fio` и `department` приходят ВСЕМ (решение человека 2026-10-14) и
  показываются без проверки блока; `tab_num`/`enterprise` режет сервер, поэтому в UI
  дополнительных гейтов нет. Маска «Сотрудник № …» — только на заявках без ФИО.
- **Карточку видят все участники согласования** (решение человека 2026-10-15): инициатор,
  владелец шага и тот, кто уже согласовал (даже если ему шаг потом переназначил
  сотрудник ОК). Гейт целиком на сервере (`requests._is_participant`) и одинаков для
  списка, счётчика «Мои задачи» и карточки — в UI проверок блоков на это нет, добавлять
  их не нужно (иначе интерфейс разойдётся с сервером). ПДн у участника обрезаны
  по-прежнему: ФИО и служба видны, `tab_num`/`enterprise` приходят `null`.
- Заместителю **бланк** доступен так же, как замещаемому, а **вложения** остались у
  владельца шага, его заместителя, ОК и админов (решение человека 2026-10-15 «бланк —
  все участвующие, вложения по рекомендации»): гейт целиком на сервере, в UI отдельных
  проверок нет. Кнопка печати — по-прежнему по блоку `print_blank`.
- Снятие шага бланка в форме заявки — по номеру шага (`dismissed_step_orders`), не по коду этапа;
  в `dismissed_stages` уходит только снятие этапов профиля/ручного маршрута.
- Форма заявки: `link_state=need_link` показываем кандидата AD и кнопку подтверждения связи;
  при блокировке маршрута — понятное действие (подтвердить/перейти в «Вручную»), не пустой экран.
- Бланк доступен и при ручном маршруте (`route_mode=custom`), снимок сохраняется в обоих режимах;
  неизвестный/отключённый бланк — 422 (`_blank_required_422`). Содержание и справочные поля 1С
  (подразделение, должность) при отправке не обязательны; обязательны предприятие, таб. номер,
  ФИО, тема. Перед отправкой — проверка с подсветкой пустых полей (`aria-invalid`), ввод снимает
  подсветку поля.
- Блок ручного маршрута смешанный: переключателя типа исполнителя нет, внутри блока доступны и
  сотрудник (модалка выбора в AD), и группа (селект, в UI — название из `step-groups`). Порядок
  шагов — кнопками «вверх»/«вниз» у каждого шага.
- **Даты форматируются только через `frontend/src/date-format.ts`** (`formatDate`,
  `formatDateTime`, `formatDateTimeHM`), зона — настройка `settings.timezone` из `/auth/me`
  (её ставит `main.tsx` до первой отрисовки). Свой `toLocaleString`/`toLocaleDateString` в
  компонентах — дыра: такие даты поедут по зоне машины. Исключение — даты БЕЗ времени
  (`hire_date`/`dismissal_date` из 1С, срок записи о заместителе): их режут строкой,
  `formatDate` их увел бы на день. Общие куски обоих разделов «Заместители» (показ срока
  `isoDateOnly`/`todayIso`/`isActiveToday`/`substitutePeriodLabel` и тип
  `SubstituteCandidate`) живут в `substitutes-shared.ts` — дубль в `substitutes.tsx` и
  `admin-settings.tsx` не заводим.
- **Правка маршрута** (`request-card.tsx`) — сотрудник ОК/admin (блок `request_create`) в статусах
  «Черновик»/«На доработке»: порядок шагов «вверх»/«вниз», удаление, добавление группы и
  сотрудника (модалка AD, логин руками не набирается). Отказавший шаг виден отдельной строкой с
  действиями «Вернуть в маршрут» (`reopen_orders`) и «Убрать из маршрута» (`drop_orders`); решение
  по нему уходит в PATCH, в пересборку маршрута он не попадает.
- **Статусы шага — строгий контракт API**: `ожидает`, `согласован`, `отклонен`, `возвращен`,
  `просрочен` (отказ **без «ё»**). Сверять статусы с константами `requests.py`, во фронте не
  разбрасывать литералы: расхождение «отклонён»/«отклонен» молча убирало отказавшего шага из
  правки маршрута.
- Причина отказа и возврата — обязательное поле формы решения (сервер `_check_comment` не примет
  решение без неё), с пояснением, что она уходит инициатору в письмо и в историю.
- Админка настроек — только для `SED_ADMINS` (settings в БД, не в коде).
- Прогон UI — через MCP `playwright` в intranet; матрицы ролей проверять после каждой правки.

## Приемка правки

Матрицы ролей из п.1 зелёные (playwright), затронутые экраны работают, ПДн не светит владельцам
сверх согласованного объёма (ФИО и служба заявки — всем, остальное обрезано на сервере).
