> всё в репо; запуск `compose up` — на стенде, сделан в рамках деплоя Волн 1–5).

База: `README.md` п.0–п.2/п.6, `AGENTS.md` (песочница: только проект, временное — в `./temp/`, ПО не ставить),
скил `debian-ops`. Секретов не вносить — только плейсхолдеры. Запуск в новой сессии: задачи 1–4 — параллельно

## Задача 1 — compose (агент: devops-compose)

* Прочитать: `README.md` п.2, `AGENTS.md`, скил `debian-ops`.
* Создать:
  * `docker-compose.yml` — сервисы `proxy, api, worker, redis, db` (образы: `nginx:stable-alpine`, `redis:7-alpine`, `postgres:17-trixie`, api/worker — локальный build); внутренняя сеть; у `db` внешнего порта нет; volumes: `pgdata, files, backups`; `certs` — read-only mount; healthcheck `db/redis`.
  * `docker-compose.prod-db-external.yml` — override: вынос `db` (внешний `DATABASE_URL`), код не трогать.
  * `.env.example` — все ключи README п.3-Инфра (`DATABASE_URL, REDIS_URL, AD_*, LDAP_CACHE_TTL, ONEC_BASES_JSON, AD_WRITE_ENABLED=false, CERT_PATH, SMTP_*`), значения-плейсхолдеры.
* Нельзя: секреты, реальные DN/URL.
* Приемка: YAML валиден, имена сервисов/сетей/volumes совпадают с README п.2.

## Задача 2 — proxy (агент: devops-proxy)

* Прочитать: те же + результат Задачи 1 (имена сервисов).
* Создать: `proxy/nginx.conf` — `80→443` редирект, `443` (cert/key из переменных mount), `location /api → api:8000`, `location / →` статика frontend, HSTS, security-заголовки; `proxy/Dockerfile` при необходимости.
* Нельзя: копировать key в образ, хардкодить домен (через переменную, дефолт `sed.company.local`).
* Приемка: конфиг синтаксически целый (ревью по тексту), пути совпадают с compose-маунтами Задачи 1.
