# AGENTS.md — обязательные правила для ИИ-агентов (СЭД)

Этот файл читается первым при любой задаче в репозитории. Детали продукта — в `README.md`. При конфликте побеждает этот файл.

## 1. Границы

* Работать ТОЛЬКО внутри папки проекта. Чтение/запись/поиск за ее пределами запрещены.
* Временные файлы, черновики, выгрузки — только в `./temp/` (создать если нет, в git не коммитить).
* Системные пути, `~/.config`, `/etc`, `/srv`, реестр, сервисы — не трогать.

## 2. ПО и окружение

* Установка чего-либо на локальный ПК (пакеты, SDK, MCP-серверы, расширения прав, изменение демонов/сервисов) — ТОЛЬКО по явному согласованию с человеком. Стоп и вопрос. Исключение — заранее выписанные разрешения в файле текущей задачи (раннере), действующие только внутри проекта и без sudo.
* Без спроса разрешено: читать/править файлы проекта, `git status/diff/log`, `docker compose config`, линт/проверка синтаксиса затронутого файла.

## 3. Объем правок

* Минимальный дифф: править только нужный кусок, соседнее не трогать, попутный рефакторинг запрещен.
* Перед правкой — прочитать файл (Read), после — проверить затронутый модуль. Сохранять стиль и контракты.
* Настройки — только в `settings` (БД) и `env` (секреты). Хардкод ФИО, групп, OU, предприятий/баз, должностей, TTL, шаблонов — запрещен.
* Язык: комментарии в коде/конфигах и документация — только по-русски.

## 4. Запреты (стоп и вопрос человеку)

* Смена архитектуры, схемы БД, контрактов API/1С, auth-потока, разделение на 2 ВМ.
* Любая запись в 1С или AD (кроме заглушки за флагом `AD_WRITE_ENABLED=false`), удаление/отключение УЗ, расширение видимости ПДн, публикация портов наружу.
* Коммиты, пуши, PR, установка ПО — только по явной просьбе.

## 5. Порядок работы

1. Прочитать `README.md` + нужный скил из `.opencode/skills/`.
2. Выполнить только свою фазу из `README.md` п.6.
3. Отчитаться: что изменено (список файлов), как проверено, что осталось открытым.

## 6. Рой, ревью и приемка

* Разработка ведется роем агентов: задачи одной фазы могут выполняться параллельно независимыми агентами, каждый — минимальный дифф в своем участке.
* Один агент — **ревьювер** (`.opencode/agent/reviewer.md`, только чтение, правок не вносит): проверяет дифф роя на минимальный объем, отсутствие хардкода настроек, сохранение контрактов, запрет записи в 1С/AD, видимость ПДн по ролям, наличие проверки затронутого модуля.
* **Основной процесс — приемщик и оценщик результата:** принимает фазу только после зеленого ревью; вправе вернуть на доработку с конкретными замечаниями. Следующая фаза не начинается без приемки текущей.
