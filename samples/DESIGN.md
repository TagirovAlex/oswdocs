# Правила дизайна для агентов (СЭД)

Эталонный макет: `samples/wssdocs_mock.html` (открыть в браузере, кнопка «Тема» переключает светлую/тёмную).
Стиль — по мотивам WSSDocs, не копия 1:1. При конфликте с этим файлом побеждает `AGENTS.md`.

## 0. Где брать структуру для работы

- **Карта проекта (где что лежит):** `STRUCTURE.md` в корне — модули/файлы/функции/стили/шаблоны/миграции. Читать обязательно.
- **План и задача дизайн-агента:** `PLAN.md`, блок G (что уже сделано, что не ломать, протокол вопросов человеку).
- **Все стили — один файл:** `frontend/src/theme.css` (токены `--sed-*`, сетки, кнопки, таблицы, dropdown, панели). Хардкод-цветов в tsx нет и не добавлять.
- **Иконки меню/темы:** `ico/*.svg` (`directory.svg`, `requests.svg`, `settings.svg`, `theme-moon.svg`, `theme-sun.svg`) + preview `ico/icons-preview.html`; логотипы — `logo-oswdocs*.svg` (в `frontend/public/` для статики).
- **Шаблоны (бланки/письма/маршруты) и их переменные:** `TEMPLATES.md` (где настраиваются, какие `{{ переменные }}`).
- **Экраны:** `frontend/src/` — `layout.tsx` (шапка/вкладки/таблица), `create-form.tsx`, `request-card.tsx`, `admin-settings.tsx`, `directory.tsx`.
- Черновики/выгрузки — только в `./temp/`, в git не коммитить.

## 1. Что обязательно соблюдать

- Цвета — только через переменные `theme.css` (`--sed-bg/surface/panel/border/text/primary/accent/radius`). Хардкод цветов в `tsx` запрещён.
- Светлая тема: шапка-модули — синий градиент, заголовок таблицы — тёмный градиент. Тёмная тема: те же места — плоские (`surface-2/border`), градиенты запрещены.
- Фильтры — один блок `filterbar` на всю ширину над списком документов (внутри правой колонки, над тулбаром/таблицей), в одну строку. Не разбивать, не переносить в сайдбар.
- Папки слева — пока плоский список со счётчиками `(N)`, иконки только CSS. Иерархическое дерево — задел на будущее, структуру под него не ломать.
- Создание (`?view=create`): верх `Этап/Статус` + две панели (слева предприятие/сотрудник/тема/содержание + файлы, справа инициатор read-only + решение/комментарий) + низ таблицей `Рассмотрение` + ссылки `Добавить последовательный/параллельный блок` + серые `ОК/Отправить/Отмена`.
- Роли из `README п.1` не менять: владелец — только свои задачи + урезанная карточка без ПДн. ПДн в макете — только примеры `УВ-...`, реальные данные не встраивать.

## 2. Заглушки

- Вид документа: таблица `doc_types` (settings), селект в форме уже включён (код автонумеруется, в выборе — наименование).
- Документ-основание: пока пропускаем. Основание — бумажное заявление (скан опционален + бегунок `DOCX→PDF`).

## 3. Что не трогать

- Логику `enterprise → employeeReady → blocks → canCreate`, поиск 1С/AD (debounce), `dirty-confirm`, гард `hr/hr_admin/admin`.
- Загрузку `getFolders/getRequests`, контракты API, схему БД, auth-поток.
- Соседние модули и рефакторинг «заодно» — запрещены (минимальный дифф).
