# Шаблоны СЭД: переменные и как их вставлять

Обновлено: 2026-10-02. Источник истины — код (`api/app/docs.py`, `api/app/mailer.py`,
`api/app/requests.py`); тексты шаблонов хранятся в `settings` БД (не в коде).

## Как вставлять переменные

Шаблоны используют **Jinja2-синтаксис** — переменная пишется в двойных фигурных скобках:

```
{{ fio }}
{{ request_id }}
```

- Внутри `{{ }}` — имя переменной (без `$`, без `%`).
- Пустые значения подставляются как пустая строка.
- Многострочный текст/тело письма можно собирать обычными строками шаблона.
- Вложенные условия/циклы Jinja2 (`{% if %}`, `{% for %}`) — по стандарту Jinja2,
  но для бланков используйте простые подстановки (docxtpl рендерит строки шаблона).

## 1. Бланки бегунка (`doc_templates`)

Настройка: `settings.doc_templates` — список `{service, category, body}`.
Подбор шаблона: по службе (`department`) + категории заявки.

Доступные переменные:

| Переменная      | Значение                                   |
|-----------------|--------------------------------------------|
| `{{ request_id }}` | Номер заявки (например `REQ-0001`)        |
| `{{ fio }}`        | ФИО сотрудника (из 1С / ручного ввода)     |
| `{{ department }}` | Подразделение/служба (поле 1С)             |
| `{{ position }}`   | Должность (поле 1С)                        |
| `{{ category }}`   | Категория заявки (пусто, если не задана)   |
| `{{ enterprise }}` | Предприятие (код/имя из настроек)          |

Пример тела бланка:

```
БЕГУНОК УВОЛЬНЕНИЯ
Сотрудник: {{ fio }}
Подразделение: {{ department }}
Должность: {{ position }}
Номер заявки: {{ request_id }}
Предприятие: {{ enterprise }}
```

## 2. Шаблоны писем (`mail_templates`)

Настройка: `settings.mail_templates` — список `{code, subject, body_html}`.
`code` — событие: `assigned` (назначена), `reminder`, `escalation`, `returned`,
`closed` и т.д. (см. `mailer.py`).

Доступные переменные:

| Переменная       | Значение                                        |
|------------------|-------------------------------------------------|
| `{{ request_id }}` | Номер заявки                                  |
| `{{ fio }}`        | ФИО сотрудника                                |
| `{{ url }}`        | Ссылка на заявку (для перехода из письма)     |
| `{{ event }}`      | Код события (служебное)                        |

Пример:

```
Тема: Назначена {{ request_id }}
Тело: Заявка {{ request_id }} назначена вам на согласование.
      Сотрудник: {{ fio }}.
      Открыть: {{ url }}
```

## 3. Шаблоны маршрутов (конструктор)

Маршрутные шаблоны задают блоки/исполнителей (в настройках «Шаблоны маршрутов»);
переменных подстановки в них нет — это структура (режим блока, исполнители-группы/сотрудники).
При выборе сотрудника-исполнителя используется поиск AD, группы — из настроек.

## Примечания

- Переменные подставляются **без ПДн сверх нужного**: бланк и письмо получают только
  перечисленные поля; ФИО владельцу-согласующему приходит (он участник процесса).
- Если шаблон отсутствует или его переменная не найдена — подставляется пусто,
  ошибкой не считается.
- Менять наборы переменных можно только вместе с кодом (контракт) — см. AGENTS.md §3.
