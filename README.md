# СЭД — Увольнение (MVP). Финальный план

Корпоративная система электронного документооборота. Первый процесс — увольнение с согласованием.
Развертывание — внутри контура, 1 ВМ Debian 13 с заделом на разделение на 2. Только открытое ПО.

## 0. Принципы работы (обязательно для агентов)

1. **Все настройки — отдельно, хардкода в коде нет.** ФИО, группы, OU, предприятия/базы, должности, TTL, шаблоны маршрутов/бланков/писем, лимиты файлов — только `settings` в БД и `env` для секретов. Новое значение — без пересборки (кроме секретов).
2. **Минимальные правки.** Агент правит только нужный кусок, не трогает соседнее, не делает рефакторинг «заодно», не меняет схему/контракты без необходимости. Перед правкой — прочитать файл, после — проверить затронутый модуль.
3. **Архитектура — только по согласованию.** Смена контейнеров, схемы БД, потока 1С/AD, auth, разделение на 2 ВМ — стоп и вопрос человеку. Запрещено молча: писать в 1С/AD (кроме будущего флага), удалять УЗ, расширять видимость ПДн, выносить порты наружу.
4. **Песочница проекта.** Запрещается выходить из папки проекта (чтение/запись/поиск — только внутри). Временные файлы, черновики, выгрузки — только в `./temp/` в проекте (создать если нет, в git не коммитить). Системные пути (`C:\Windows`, `~/.config`, `/etc`, `/srv` и т.п.) не трогать.
5. **ПО на локальном ПК — только по согласованию.** Установка пакетов, SDK, драйверов, MCP-серверов, расширение прав, изменение сервиса/демона — стоп и вопрос человеку. Разрешено без спроса только: чтение/правка файлов проекта, `git status/diff/log`, локальный `docker compose config`/линт.

## 1. Зафиксированные решения

* **ОС/стек:** Debian 13, 1 ВМ (`4 vCPU / 8 ГБ / 100 ГБ` — уточнит ИТ к тесту). `Nginx + Postgres 17 + Python 3.12 FastAPI + Redis 7 + React SPA`, Docker Compose. Контейнеры: `proxy, api, worker, redis, db` (5). Frontend — статика в `proxy`.
* **Сайт:** intranet, HTTPS на корпоративном сертификате (read-only mount в Nginx). DNS/сертификат/порты — дает ИТ к тесту.
* **Auth:** доменные логин+пароль через LDAPS bind, проверка `memberOf` по группам из настроек. Пароли не храним. OU `OSWDOCS` + группы (`SED_HR, SED_ADMINS, SED_STEP_EXEC` — три основные на старте, раскладка остальных позже) + RO-учетку создает ИТ к тесту, пути — в настройках.
* **AD — только чтение:** `manager`, подразделение/должность, группы, `mail`. Стыковка 1С↔AD только по полному ФИО, при расхождении истина — 1С, решает ОК вручную (`link_1c_ad`).
* **1С ЗУП — только чтение:** несколько баз на 1С web-сервере. В настройках — предприятия → привязанные базы с путями + сервисная УЗ чтения на каждую. сценарий ОК: предприятие → сотрудник. Ключ `enterprise+base_code+tab_num`. Значимые действия в 1С/AD — только люди руками.
* **Единая карточка:** `1С (предприятие, таб.№, ФИО, подразделение, должность, вид занятости, дата приема, остаток отпуска — только ОК)` + `AD (sam, manager, dept/title, memberOf, mail — только для уведомлений)`. Категории `МОЛ/линейный/руководитель` через таблицу `position_to_category` (ручное заполнение после запуска). Флаг МОЛ из 1С — TODO.
* **Процесс:** бумажное заявление (скан опционален) → заявка только от ОК (`SED_HR`) → шаблон по службе/категории или ручной конструктор (только разрешенная группа, замена руководителя, fallback если шаблона нет) → генерация бегунка DOCX→PDF с QR → печать на обычном принтере → отметки владельцев шагов (любой из группы, отметка = решение + дата + автор + комментарий: при согласовании опционален, при отказе/возврате обязателен, шаблон может требовать всегда) → сверка ОК → закрытие. Статусы: `Черновик → На согласовании → На доработке → Согласовано → К исполнению → Завершено / Отклонено / Отозвано`.
* **Бланки/письма:** `doc_templates` по службе+МОЛ в корп. виде (образцы к тесту, разметка подписи перед запуском), версии `v1/v2`. `mail_templates` (Jinja HTML) под корп. вид. Печать/письма — через `worker` (`python-docx-template → LibreOffice PDF`, SMTP Exchange).
* **Уведомления/эскалация:** Exchange SMTP на `mail` из AD. События v1: `назначена → напоминание → эскалация → закрыта/возврат` (правки после пилота). Эскалация включаемая по `position_escalation` должности увольняемого. TTL отметок `approval_ttl_days`, общего дедлайна нет.
* **Поиск/доступ:** по ФИО/логину после логина. ОК — все + полная карточка, владелец — только свои задачи + урезанная без ПДн, админы — все + настройки, остальные — ничего.
* **Файлы/ПДн:** скан — глобальные `retention_days / max_mb / форматы`. Чувствительные поля — только ОК.
* **Задел:** `AdLifecycle.disable (AD_WRITE_ENABLED=false)` — только disable, никогда delete. Автосинхронизация AD+1С — backlog (регламентный worker + очередь сверки ОК).

## 2. Архитектура

```
Browser --HTTPS--> proxy (nginx :80→443 + :443, корп. cert)
  /api -> api (fastapi:8000, stateless)
  /    -> frontend static
  api/worker -> db (postgres:17, volume, без внешнего порта)
  api/worker -> redis (broker + кэш)
  api/worker -> AD LDAPS:636 (read)
  api/worker -> 1С web (GET, multi-base, read)
  worker -> Exchange SMTP
```

Хост: Docker CE, nftables, `/srv/sed/{pgdata,files,backups,certs}`, `sed.service`. Разъезд на 2 ВМ — вынос `db` + смена `DATABASE_URL`.

## 3. Каталог настроек (все вне кода)

Инфра (`env`, секреты): `DATABASE_URL` (= `PG_URL` для MCP postgres, см. AI_SKILLS_MCP.md), `REDIS_URL, AD_URL/BASE_DN/READER_DN+secret, LDAP_CACHE_TTL, ONEC_BASES_JSON (enterprise→base→url+user+secret), AD_WRITE_ENABLED=false, CERT_PATH, SMTP_USER/SMTP_PASSWORD` (учётка релея — секреты).
Прикладные (`settings` в БД, правит `SED_ADMINS`): `sed_ou, allowed_ad_groups, enterprises, position_to_category, position_escalation, approval_ttl_days, require_paper_signature, require_comment (на шаг, по умолчанию false; отказ/возврат — всегда обязателен), smtp_host/smtp_port/smtp_from (параметры SMTP-релея, с 2026-09-30 в settings), templates/filters/steps, doc_templates, mail_templates, scan_retention_days/scan_max_mb`.

## 4. Схема Postgres (ядро)

`users(sam, fio_full, dept_ad, title_ad, manager_dn, mail)`; `one_c_bases(code, enterprise, name, odata_url)`; `employee_base_map(enterprise, base_code, tab_num, fio, dept_1c, position_1c, mol_flag TODO)`; `link_1c_ad(enterprise, base_code, tab_num, sam, by, at, verified)`; `dismissal_requests(... enterprise, tab_num, base_code, initiated_by_hr, route_origin, snapshot_1c/ad ...)`; `request_steps(request_id, order, owner_group, done_by, status, done_at, expires_at, comment)`; `documents(request_id, version, docx/pdf)`; `attachments(...)`; `templates/steps/filters`; `settings`; `mail_templates/mail_queue`; `audit_log` append-only.

## 5. НФТ

TLS 1.2+, HSTS, сессии 10 ч (решение бизнеса 2026-09-30: рабочий день; исходное НФТ 15–20 мин отменено владельцем), rate-limit логина, RPO 24ч/RTO 4ч (уточнить к тесту), `pg_dump` + снапшот, ПДн по ролям.

## 6. План работ для агентов

Фазы строго по порядку, следующую не начинать без зеленой предыдущей. Каждый агент перед стартом читает этот README и свой скил. Разработка — роем (параллельные агенты по независимым участкам фазы), один агент — ревьювер (только чтение, чек-лист в `.opencode/agent/reviewer.md`), основной процесс (координатор, полные права) — создает чек-лист ревьювера до старта роя, приемщик и оценщик результата (принимает фазу после зеленого ревью, возвращает на доработку с замечаниями).

* **Фаза 0 — devops-scaffold:** `docker-compose.yml (+prod-db-external override), .env.example, /srv/sed layout, Nginx+cert mount, sed.service`. Приемка: файлы + зелёное ревью; запуск `compose up` на чистой Debian 13, `proxy` отдает 443, `db/redis` healthy — на тестовой ВМ (к тесту, ИТ), в песочнице не выполняется. Без бизнес-логики.
* **Фаза 1 — dba:** миграции (Alembic): все таблицы п.4 + индексы `pg_trgm` на ФИО/`sam` + сиды `settings` по умолчанию. Приемка: миграции вверх/вниз, `audit_log` только insert.
* **Фаза 2 — backend-auth-card:** LDAPS bind + группы из настроек + `GET /me`, `GET /employees?enterprise&q (ФИО/логин)` с ролевой обрезкой, `link_1c_ad` + снапшот (истина — 1С). Приемка: нет в группе → 403, ПДн не светит владельцам.
* **Фаза 3 — backend-1c:** `OneCClient` per-base GET + выбор `предприятие→сотрудник`, кэш Redis, составной ключ. Приемка: одна база down → остальные работают, таймауты 5с.
* **Фаза 4 — backend-route-doc:** шаблоны + `position_to_category/escalation` + ручной конструктор (только разрешенная группа) + `request_steps` + генерация DOCX→PDF с QR/версиями + `mail_queue` + эскалация. Заглушка `AdLifecycle.disable` за флагом, вызов запрещен. Приемка: нет шаблона → ручной; повторная печать → `v2`.
* **Фаза 5 — frontend:** логин, создание ОК (предприятие→сотрудник→маршрут→печать), отметки владельца (только свои), админка настроек (`SED_ADMINS`). Приемка: матрицы ролей из п.1.
* **Фаза 6 — qa/security:** негативные тесты (403, дубли ФИО, просрочка TTL, лимиты скана, rate-limit), проверка «нет записи в 1С/AD, нет delete». Приемка: чек-лист + `audit_log` полный.
* **Фаза 7 — pilot:** деплой на 1 ВМ, Exchange/DNS/cert от ИТ, образцы бланков, списки должностей. Правки событий писем — только после пилота.
