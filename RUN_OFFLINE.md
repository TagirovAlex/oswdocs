# Раннер: весь возможный код без тестовой ВМ

Цель — написать код фаз 1–5 с тестами на моках. Живая интеграция (ВМ, AD, 1С, SMTP, PDF, compose up) —
отдельный слой приемки на стенде по `deploy/ЧЕК-ЛИСТ_ИТ.md`, здесь НЕ выполняется.

База: `README.md`, `AGENTS.md` (песочница: только проект, временное — в `./temp/`, установка ПО/долгие
серверы/публикация портов — только по согласованию), скилы из `.opencode/skills/`.
Правило моков: границы `LDAP / 1C HTTP / SMTP / LibreOffice / Postgres-live` — только фейки и фикстуры;
боевые вызовы заворачивать в интерфейсы (`AdReader, OneCClient, Mailer, DocRenderer`), чтобы на стенде
подменить реализацию без правки логики. ПДн в фикстурах — только вымышленные.

## Режим автономности (предварительные разрешения человека на весь раннер)

Цель — ноль вопросов до приемки. Вместо вопросов агент пишет предположение в `./temp/DECISIONS.md`
(не коммитить) и идет дальше. Стоп и запись в `./temp/BLOCKERS.md` — только если: нужна смена
архитектуры/схемы/контракта, нужен реальный секрет или живой стенд, задача невыполнима на моках.

Разрешено без доп. согласования (только в пределах проекта, без sudo):
* проверить тулчейн (`python3 --version`, `node --version`); если чего-то нет — НЕ ставить системно,
  а работать дальше (код + тесты), пометив непрогоняемое в `OFFLINE_GAPS.md`;
* `python -m venv ./temp/.venv` + `pip install` из `requirements.txt` (только PyPI, без системных пакетов);
* `npm ci` внутри `frontend/` + локальные `npx` (jest/vite) из `node_modules`, без `npm install -g`;
* запускать `pytest/jest/vite build`, эфемерные localhost-серверы самих тестов (слушать только 127.0.0.1,
  наружу ничего не публиковать);
* создавать/править файлы только внутри проекта; коммиты и пуши — запрещены даже здесь.
Запрещено как обычно: `sudo/apt`, Docker-демон, системные сервисы, правка вне проекта, реальные секреты.

Запуск в новой сессии: волны строго по порядку (следующая — после зеленого ревью предыдущей),
задачи внутри волны — параллельно независимыми агентами. После каждой волны — ревьювер
(`.opencode/agent/reviewer.md`), приемка — основной процесс.

## Волна A — скелеты и клиенты (параллельно, 5 агентов)

### A1 — dba-миграции (скил `pg-sed`)
* Файлы: `db/alembic/*`, `db/seeds/*` — все таблицы README п.4, индексы `pg_trgm` на ФИО/`sam`,
  `audit_log` append-only, сиды `settings` (группы, `sed_ou`, `approval_ttl_days`, `position_escalation`,
  `position_to_category`, `require_paper_signature`, `require_comment`, `scan_*`).
* Приемка: ревью SQL-текста; накат/откат — пометка «на стенде» (без живого Postgres не гонять).

### A2 — backend-скелет (скил `fastapi-sed`)
* Файлы: `api/app/{main,config,deps,audit}.py`, `api/requirements.txt` (реальные зависимости),
  `api/tests/conftest.py` (фикстуры, TestClient). Конфиг — только env/settings, `AD_WRITE_ENABLED=false`.
* Приемка: `pytest api/tests -q` зеленые (health, 403 без группы на моке, обрезка ПДн).

### A3 — 1С-клиент (скил `onec-multibase`)
* Файлы: `api/app/onec_client.py` (per-base GET, таймаут 5с, circuit-breaker), `api/app/resolver.py`
  (`предприятие→база→сотрудник`, ключ `enterprise+base+tab`), `api/tests/test_onec*.py` на mock-HTTP,
  фикстуры карточек (вымышленные ФИО).
* Приемка: pytest зеленые, падение одной базы не валит остальные (тест).

### A4 — AD-ридер (скил `ad-reader`)
* Файлы: `api/app/ad_reader.py` (bind, `manager/memberOf/mail`, кэш-интерфейс), `api/tests/test_ad*.py`
  на фейковом LDAP (фиктивный `manager`-цепочки, группы `SED_*`).
* Приемка: pytest зеленые, истина при расхождении — снапшот 1С (тест).

### A5 — frontend-скелет (скил `react-sed`)
* Файлы: `frontend/{package.json, vite.config, src/{layout,api-mock,theme}.tsx}` — сетка по ориентиру
  (вкладки, дерево папок со счетчиками, таблица, фильтры, тулбар), светлая тема в синей гамме через
  CSS-переменные (задел под темную), MSW-моки API.
* Приемка: `npm test/build` зеленые на моках (если Node нет — стоп и вопрос, без самодеятельности).

## Волна B — логика на моках (параллельно, 4 агента; вход — волна A)

### B1 — auth+карточка (скилы `fastapi-sed`, `ad-reader`)
* Эндпоинты `/auth/me`, `/employees?enterprise&q`, `link_1c_ad`, снапшоты `snapshot_1c/ad`.
  Роли: ОК — полная карточка, владелец — урезанная без ПДн, остальные — 403/пусто.
* Приемка: pytest (матрица ролей, дубли ФИО → ручная сверка).

### B2 — заявки+маршруты (скилы `fastapi-sed`, `approval-templates`)
* Эндпоинты `/requests`, `/requests/{id}/steps` (шаблон/конструктор, замена руководителя,
  правка только разрешенной группой + `audit_log`), `position_to_category/escalation`,
  `require_comment` (согласие — опц., отказ — обязат.), TTL отметок.
* Приемка: pytest (нет шаблона → ручной, просрочка → повтор, отказ без комментария → 422).

### B3 — документы+письма (скилы `mail-docs`, `fastapi-sed`)
* `DocRenderer`: DOCX из `doc_templates` (Jinja, QR `request_id`, версии `v1/v2`) — реально;
  PDF — стаб с пометкой «рендер на стенде (LibreOffice)». `mail_queue` + `mail_templates`
  (отправка — mock `Mailer`, ретраи).
* Приемка: pytest (DOCX собирается, QR ведет на заявку, очередь переживает рестарт worker-мока).

### B4 — экраны (скил `react-sed`)
* Экраны из раздела «Данные для UI»: список, карточка (блоки 1С-только-ОК/AD/маршрут/документы/история),
  форма создания ОК, урезанная карточка владельца, админка настроек. Все на MSW-моках волны B1–B3.
* Приемка: jest/Storybook зеленые, ПДн не светит владельцу (тест).

## Волна C — тесты и сводка (параллельно, 2 агента; вход — волна B)

### C1 — негативные тесты кодом (скил `qa-sed`)
* `api/tests/test_negative*.py`: 403, дубли ФИО, TTL, лимиты скана, rate-limit, «нет записи в 1С/AD»,
  полнота `audit_log`. Прогон — локально на моках; прогон на стенде — пометка «на ВМ».
### C2 — сводка расхождений
* Файл `./temp/OFFLINE_GAPS.md` (не коммитить): что осталось только для стенда
  (накат миграций, живой bind/OData/SMTP, PDF, compose up, playwright) + что спросить у ИТ.

## Ревью и приемка

* После каждой волны — ревьювер: минимальный дифф, настройки без хардкода, read-only границы,
  ПДн по ролям, тесты волны зеленые. Вердикт `ПРИНЯТО / НА ДОРАБОТКУ`. Вопросы рою запрещены:
  замечания ревью устраняются следующей итерацией той же волны, блокеры — только в `BLOCKERS.md`.
* Приемка offline-пакета основным процессом: волны A–C зеленые + `OFFLINE_GAPS.md` полон.
  Следствие: код готов к стенду; интеграционная приемка — на тестовой ВМ по чек-листу ИТ.
