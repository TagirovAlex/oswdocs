# QA стенда — матрица ролей, аудит, НФТ (W5c Волны 5)

Каталог проверок качества для стенда (1 ВМ, Debian 13). Запуск — ТОЛЬКО на ВМ
после деплоя, локально не гонять: нужны реальные LDAPS/Redis/1С и доменные
учетки. Код приложения здесь не меняется — только чтение/скрипты.

Состав:

## 1. Матрица ролей (playwright)

### Установка

Playwright ставится один раз на машине прогона (на ВМ или с машины QA через VPN):

```bash
npm init -y
npm install -D @playwright/test
npx playwright install chromium
```

### Переменные окружения (секреты — только env, не в коде)

```bash
export SED_BASE_URL=https://sed.company.local
export LOGIN_ADMIN=...   PASS_ADMIN=...
export LOGIN_HR=...      PASS_HR=...
export LOGIN_OWNER=...   PASS_OWNER=...
```

Учетки — реальные доменные из групп `SED_ADMINS`, `SED_HR`, `SED_STEP_EXEC`
(или группы шага). Учетка не задана в env — тест роли пропускается (skip).

### Запуск

```bash
npx playwright test roles-matrix.spec.ts --reporter=line
```

### Что покрывает (README п.1 «Поиск/доступ» и матрица ролей)

| Роль | Вкладки (layout.tsx) | Создание | Настройки | Карточка |
|------|----------------------|----------|-----------|----------|
| admin | Заявки / Создание / Настройки | мастер открывается | форма + `GET /api/settings` 200 | полные колонки с ПДн |
| hr | Заявки / Создание | мастер открывается | вкладки нет, API 403 | полные колонки с ПДн |
| owner | Заявки | вкладки нет | вкладки нет, API 403 | колонка-маска, `fio/tab_num/enterprise=null`, ячейка «Сотрудник № …» |
| guest | нет (экран логина) | нет | `GET /api/*` → 401 | данных нет |

Отдельно проверяется: число вкладок ровно по роли (лишних нет), ПДн
владельцу не отдает API (не только скрывается в UI).

## 2. Полнота audit_log

После прогона ролевых сценариев:

```bash
psql "$DATABASE_URL" -f audit-fullness.sql
```

Проверяет: счётчики (всего/за сутки/за 24ч), события за день по `action`,
топ-акторов, отсутствие событий без `actor`, разбивку по сущностям,
append-only (UPDATE/DELETE обязаны падать — триггер), полноту ключевых
`action` за день. Пустая строка п.7 — действие не аудируется (дыра полноты).

## 3. НФТ — nft-checklist.md

Чек-лист закрывается вручную/скриптами перед приемкой Фазы 6: TLS 1.2+/HSTS,
сессии 15–20 мин, rate-limit логина (Redis), RPO 24ч/RTO 4ч, ПДн по ролям.

## 4. Что проверяется ВРУЧНУЮ (не автоматизировано)

- **Печать бегунка PDF/QR** (`POST /api/requests/{id}/print`): генерация
  DOCX→PDF через LibreOffice, QR с ссылкой на заявку, версии `v1`/`v2`.
  Проверка — печать на обычном принтере, скан/внешний вид бегунка.
- **Почта (SMTP Exchange)**: письма `назначена → напоминание → эскалация →
  закрыта/возврат` из `mail_templates`; доставка на `mail` из AD.
- **Сканы-вложения**: загрузка, лимиты `scan_max_mb`/`scan_retention_days`,
  ошибки 413/415/409.
- **Эскалация и просрочка TTL** — через worker по расписанию.
- **Резервное копирование** — `pg_dump` + снапшот (см. `deploy/LAYOUT.md`).
