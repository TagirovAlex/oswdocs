# Чек-лист ИТ к тесту (СЭД, Фаза 0)

Что нужно от ИТ до запуска тестовой ВМ. Значения — плейсхолдеры в угловых
скобках; реальные хосты/секреты/DN сюда не вносить (только `.env` на ВМ
и `settings` в БД через `SED_ADMINS`).

## 1. DNS и сеть

- [ ] DNS-имя intranet для стенда: `<intranet-fqdn>` (дефолт в конфигах — `sed.company.local`).
- [ ] Доступность сайта только внутри контура; наружу — только `:80` (редирект на `:443`) и `:443`.

## 2. Сертификат и ключ (корпоративные)

- [ ] Выпустить cert/key: CN/SAN = `<intranet-fqdn>`, срок действия: `<дата окончания>`.
- [ ] Положить на ВМ: `/srv/sed/certs/` (каталог `700`, `root:docker`; mount в `proxy` read-only).
  - сертификат: `/srv/sed/certs/<имя>.crt`
  - ключ: `/srv/sed/certs/<имя>.key` (в образы не копировать).
- [ ] Путь к сертификату указать в `env` (`CERT_PATH`) на ВМ.

## 3. Сетевые открытия с ВМ

- [ ] LDAPS к контроллерам домена, порт `636`: хосты `<ad-host-1>`, `<ad-host-2>`.
- [ ] 1С web-сервер (OData, чтение): URL баз `<https://1c-web/...>` (по числу предприятий/баз).
- [ ] SMTP-релей Exchange: хост `<smtp-host>`, порт `<25/587>`, from-адрес `<noreply@...>`.

## 4. Active Directory

- [ ] OU для области видимости: `OSWDOCS` (заведен; точное DN — в настройке `sed_ou`, правит `SED_ADMINS`).
- [ ] Группы (заведены в `OSWDOCS`, три основные): `SED_HR` (создание заявок — только ОК),
  `SED_ADMINS` (настройки), `SED_STEP_EXEC` (единая группа исполнителей; разбивка по ролям — позже).
- [ ] Сервисная RO-учетка для LDAP bind (только чтение: `manager`, подразделение/должность,
  группы/`memberOf`, `mail`): DN `<reader-dn>`, секрет — в `env` на ВМ (`AD_URL`, `BASE_DN`,
  `READER_DN` + секрет, `LDAP_CACHE_TTL`).
- [ ] Пути OU/групп/DN вносятся в настройки (`settings`/`env`), а не в код.

## 5. 1С ЗУП (только чтение)

> Статус (2026-09-30): механизм готов — базы 1С (`onec_bases`) и источник списка
> предприятий (`onec_enterprises_source`) вносятся в settings через админку (инфра, admin);
> пароли маскируются. Ожидается OData-контракт: точные пути сущностей (карточка сотрудника,
> список предприятий) и учётка чтения на базу.

- [ ] Список предприятий и привязанных баз: `предприятие → base_code → OData-URL` (в settings `onec_bases`).
- [ ] Сервисная УЗ чтения на каждую базу: логин, пароль (в settings `onec_bases`/`onec_enterprises_source`, маскируется).
- [ ] OData-контракт списка предприятий для синхронизации (ответ: список `[{code,name}]` или `{"enterprises":[...]}`) — источник `onec_enterprises_source`; синхронизация еженедельно + кнопка «Обновить из 1С».
- [ ] Составной ключ сотрудника: `enterprise + base_code + tab_num`; истина при расхождении ФИО с AD — 1С.

## 7. Ресурсы ВМ

- [ ] `4 vCPU / 8 ГБ / 100 ГБ`, Debian 13, Docker CE (уточнить к тесту).
- [ ] Хост-каталоги `/srv/sed/{pgdata,files,backups,certs}` (права — см. `deploy/LAYOUT.md`).
- [ ] systemd-юнит `deploy/sed.service` установлен на ВМ, `WorkingDirectory=/srv/sed`.

## 8. Бэкапы и НФТ

- [ ] RPO `24ч` / RTO `4ч` (README п.5, уточнить к тесту).
- [ ] Место хранения бэкапов (вне ВМ): `<целевое хранилище/путь>`.
- [ ] Регламент: периодичность `pg_dump` (ежедневно, в `backups` как staging), ротация выгрузок,
  снапшоты ВМ/тома (физический уровень для `pgdata`), ответственный и порядок восстановления.
- [ ] Перед применением миграций (например, справочника бланков 0012/0013) — разовая копия БД
  `pg_dump` с меткой; на стенде отработало размещение выгрузки в `/srv/sed/backup/<метка>`.
- [ ] Бэкапится: `pg_dump` + `files` целиком + выгрузки `backups`; `certs` — нет (перевыпуск через ИТ).
- [ ] Остальное НФТ: TLS 1.2+, HSTS, сессии 15–20 мин, rate-limit логина (проверка — Фаза 6).
