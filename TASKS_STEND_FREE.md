# Свободный забег стенда: всё, что не требует данных от ИТ

База: `README.md`, `AGENTS.md`, `deploy/LAYOUT.md`, `deploy/ЧЕК-ЛИСТ_ИТ.md`,
`temp/OFFLINE_GAPS.md`. Доступы ВМ — в `./.env` (`SED_VM_*`, в git не коммитить).
Хелперы SSH — `./temp/ssh_probe.py` (команды), `./temp/su_exec.py` (root через su),
`./temp/sftp_put.py` (заливка). Пароли в команды НЕ вставлять — скрипты сами читают `.env`.

ВМ: `oswdocs` 10.0.70.117, Debian 13, Docker 29.8.1 + Compose v5.5.1, код в `/srv/sed`
(`config` валиден, `.env` на ВМ пустой, `sed.service` установлен, disabled).

## Жесткие запреты забега

* Полный `compose up` запрещен (нет серта и `.env` — proxy упадет). Частичный `up db/redis`
  и `run --rm` — только своим агентам и только свои сервисы.
* `sed.service` не включать/не стартовать. `.env` на ВМ не заполнять (пустой, 600).
* Сертификаты: только временный self-signed для проверки конфига nginx с ОБЯЗАТЕЛЬНЫМ
  удалением после проверки. Корп. серт — только от ИТ.
* Коммиты/пуши — запрещены (приемщик коммитит отдельной командой).
* Комментарии в коде/конфигах — только по-русски. Временное — только `./temp/`.

## Волна S1 — образы (1 агент; вход — текущий стенд)

### S1 — vm-images (без скила, хост-операции)
* На ВМ как root: `docker compose --project-directory /srv/sed build api worker`
  (тот же образ, разные команды). Замерить время и размер образов.
* Приемка: обе сборки успешны, `docker images` показывает образы, лог в отчете.
* Нельзя: менять Dockerfile/requirements/compose (только сборка).

## Волна S2 — параллельно, 3 агента (вход — образы S1 собраны)

### S2a — vm-db (скил `pg-sed`, разделы миграции/бэкапы)
* На ВМ: `up -d db redis`, дождаться healthy; накат миграций из `/srv/sed/db`
  (через собранный образ api: `compose run --rm api alembic upgrade head`),
  проверка сидов `settings` (10 ключей), затем `downgrade -1` + снова `upgrade head`
  (проверка вверх/вниз на живом Postgres 17); пробный `pg_dump` в volume backups.
* Приемка: upgrade/downgrade без ошибок, сиды на месте, дамп создан.
  `audit_log` — только insert (проверка триггера попыткой update).
* Нельзя: трогать compose-файлы, заполнять `.env`, стартовать api/worker/proxy.

### S2b — frontend-static (скил `react-sed`, разделы сборка/статика)
* Локально в репо: минимальный дифф `docker-compose.yml` — доставка `dist` фронта
  в `proxy:/usr/share/nginx/html` (именованный volume или bind — решить и обосновать
  в отчете; ключ в образ не копировать, certs не трогать). Залить измененный compose
  на ВМ, `config` валиден. Собрать фронт (`npm run build` локально или build на ВМ),
  доставить `dist` в volume/каталог, проверить отдачу по HTTP (80): `curl -sI`.
  Проверку 443 — только с временным self-signed (создать в /tmp, mount override,
  после проверки УДАЛИТЬ ключ и серт, зафиксировать удаление в отчете).
* Приемка: `config` зелен, index.html отдается, временные ключи удалены.
* Нельзя: полный up, правки nginx.conf без нужды, трогать api/db.

### S2c — vm-firewall (без скила, хост-операции)
* На ВМ: проверить наличие `nftables` (если нет — `apt install` и зафиксировать);
  базовый набор: разрешить loopback, established, SSH (22), 80/443 внутрь;
  всё остальное входящее — drop. Persist через `nftables.service`.
  Сначала убедиться, что правило 22 не отрежет текущую SSH-сессию (применять атомарно,
  проверка новым подключением ПЕРЕД выходом).
* Приемка: `nft list ruleset` в отчете, новое SSH-подключение успешно.
* Нельзя: закрывать 22 до проверки, трогать docker-цепочки сверх минимума, правила наружу.

  минимальный дифф, без секретов в репо, ВМ-операции только разрешенные,
  временные ключи удалены, `sed.service` по-прежнему disabled, полного up не было.
* Вердикт `ПРИНЯТО / НА ДОРАБОТКУ`. Вопросы рою запрещены, блокеры — в `temp/BLOCKERS.md`.
* Приемка свободого забега основным процессом: S1–S2 зеленые. Дальше — только
  по данным ИТ (сертификат, `.env`, AD/1С/SMTP, бланки, должности).
